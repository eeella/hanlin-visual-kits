## 2026-09-09 下半場：上面那個「改了三輪仍然一樣」已找到根因並修好

用 headless Chrome + CDP 對引擎做變體矩陣，複製使用者描述的形狀（頂部導覽＋左側純 div
題目清單＋右側工作區，滿版高度寫在內層 `.app`），**自動判定仍然 false 並補上 hero**。
逐一換掉單一變數之後定位到：

**根因＝三條放寬全部掛在 `hasShellStructure`（有側欄＋雙欄）之下，而側欄選擇器一個字都沒改。**
`SBEL` 原本只認 `aside` 與 class 含 `sidebar`／`side-nav`／`sidenav`／`side-bar`／`drawer`。
實測 `class="side"`、`class="left-panel"`、`class="q-list"`、`<nav class="side">`、
`role=navigation` 全部認不出來 → 側欄 null → 放寬條件一條都不會生效。

另外抓到兩個把放寬變成死碼的問題：
- `if(!css)return false`：純 utility class 的頁面一條 `<style>` 都沒有，
  偏偏 ③ `utilShell` 就是為它寫的，卻在它前面先被擋掉
- 三條放寬都硬要 `overflow:hidden`：app shell 的「各欄各自捲動」實際多半寫成
  `.side{overflow:auto}`／`overflow-y:scroll`，分欄層根本不寫 hidden

### 修了什麼
1. `SBEL` 改四段式：命名 → 詞界 token 白名單 → 分欄容器的窄第一欄 → 窄欄 `<nav>`。
   用 token 不用 `[class*=side]`（否則 `outside`／`beside` 誤中）
2. 拿掉 `if(!css)return false`
3. `scrollContained` 認 `hidden|auto|scroll|overlay|clip`，class 形式也認
4. `utilShell` 掃全頁 class（Tailwind 的 `h-screen` 常在中層 wrapper），不再只看 body 與其直屬子元素
5. **迴歸抓到的新誤判**：放寬成「認所有 `<nav>`」之後，`demo/hanlin-baihuawen` 的
   `<nav class="tabs" role="tablist">` 立刻被標成側欄。加上 `tabLike()` 排除
   （`role=tablist|menubar|toolbar`、class token `tabs`/`tab-bar`/`breadcrumb`/
   `pagination`/`segmented`/`pills`）與「CSS 限成窄欄」的要求

### 驗收（都是實際渲染量測，不是看規則有沒有寫進檔案）
- 命名變體 7/7、寫法變體 7/7 全部判定 app shell 且不補 hero
- 專案 6 個 demo 樣本：套版輸出與修正前**位元組完全相同**（同時載入新舊兩份引擎直接比對，

## 2026-09-09 真實 UI 端到端驗證（引擎層過了不等於使用者看得到）

前面的驗收都是直接呼叫 `brandifyHtml`。改用 CDP 驅動**真正的匯入頁 UI**
（貼上內容 → 點「解析貼上的內容」→ 讀「套入資訊」面板）之後，又抓到兩件事：

**① 面板謊報版面型態。** 結構判定整段掛在「套用項目」的**語意結構**底下，
而它**預設不勾**。先前報告直接讀 `res.appShell` 的初始值 `false`，於是沒勾的時候
面板照樣寫「一般頁面（文件流）」＋「這是自動判定的」——連手動指定「應用型版面」
都被顯示成「一般頁面　← 你手動指定的」。三重誤導：沒判定、講成判定過、
還把使用者的指定顯示成相反的結果，而這個面板正是他診斷版面問題的唯一依據。
修法：`brandifyHtml` 回傳 `structRan`，未判定時面板寫「未判定」，
並說明原因與「本次不生效」，`補歡迎橫幅` 同步改成「不補（本次沒做結構判定）」。

**② 語意結構沒勾時不會補橫幅**（引擎層實測六組確認），所以手動覆寫在那個狀態下
沒有東西可以壓制——不是功能壞掉，是回報壞掉。

驗證過程本身踩到的三個坑（下次要驅動這個 UI 直接照抄）：
- 樣本沒有可辨識的品牌色會被 alert 擋下（`匯入失敗：檔案裡找不到可辨識的品牌色`），
  CDP 要掛 `Page.javascriptDialogOpening` 自動接受，否則 `Runtime.evaluate` 永不回應、
  整支腳本靜默卡死（順手替所有 CDP 呼叫加逾時）
- 沒挑套版就只顯示對照、不跑套用引擎。要讓 `isStyled()` 為真，
  `hanlin-brand-theme` 的 `theme.n` **必須對得上某一組 kit 的名稱**
  （`HL_QUICK_DEFAULT` 的「翰林藍」對不上「翰林學習藍」），
  否則 `hasPickedKit()` 為 false，`clearPrevious()` 會把旗標清掉
- 報告在 `<details>` 裡，收合狀態 `innerText` 回空字串，要 `open=true` 或讀 `textContent`

### 真實 UI 六種情境（全部通過）
| 情境 | 版面型態 | 補歡迎橫幅 |
|---|---|---|
| app shell，語意結構沒勾 | 未判定 | 不補（本次沒做結構判定） |
| 同上，手動指定應用型版面 | 未判定（你指定了「應用型版面」，本次不生效） | 同上 |
| app shell，勾選＋自動 | **應用型版面（側欄＋主工作區）** | 不補（app shell 補了會蓋掉工作區） |
| 同上，手動指定一般頁面 | 一般頁面（文件流）**　← 你手動指定的** | 依採用設定（實際補了橫幅） |
| edcafe-navy，勾選＋自動 | 應用型版面 | 不補 |
| map-history-trail，勾選＋自動 | 一般頁面 | 依採用設定 |
