# 翰林 Web 基本範例

只需要基本規範的人，下載這個資料夾就能直接開工。

沒有建置流程、沒有相依套件、沒有 npm。用瀏覽器打開 `index.html` 就會看到成品。

依據：同目錄上層的 `STYLEGUIDE.md`（翰林相信學習 — 設計系統規範）。

---

## 檔案

| 檔案 | 是什麼 | 你會不會改它 |
|---|---|---|
| `index.html` | 示範頁。頁首、Hero、篩選、卡片、按鈕七態、表單、Accordion、頁尾 | 會，這是你的起點 |
| `tokens.css` | 設計 token。**唯一的數值來源** | 換品牌色時只改這裡 |
| `styles.css` | 元件樣式。全部引用 token，不含任何色碼 | 加元件時改這裡 |
| `app.js` | 基本互動：chip 鍵盤操作、Accordion、表單驗證 | 視需要 |
| `favicon.svg` | 網站頁簽 icon（翰林 H 標） | 不用改 |

品牌標誌不是獨立檔案 —— 規範 §3.11 要求以 inline SVG 內嵌，這樣文字墨色才能綁定 `--logo-ink`，
在淺色底與深色底自動切換。標誌直接寫在 `index.html` 的頁首與頁尾裡，複製整段 `<a class="logo">` 即可。

---

## 怎麼跑

直接雙擊 `index.html` 就能看。若要完整測試（含字體載入），用 http 開：

```
python3 -m http.server 8000
```

然後開 http://127.0.0.1:8000/

## 改的規矩

**只改 `tokens.css`。** 這是規範第 1 節列的成功條件：

> 所有介面數值必須來自 `tokens.css`，不得在元件層寫入色碼或一次性尺寸。

換品牌色時改 `--color-action-bg` 那幾個變數，整站會一起變。
在 `styles.css` 裡寫死 `#064ea4` 這種色碼，就是規範第 6 節列的反模式第一條。

改完顏色請重新確認對比度：正文 ≥ 4.5:1、大字與元件邊界 ≥ 3:1。

## 響應式

斷點取自規範 §2.5：**860px**（導覽收合、雙欄轉單欄）、**640px**（Hero 縮小、選單滿寬）。

已在 320 / 375 / 768 / 1024 / 1280 / 1440 六個寬度實測，全部通過：

- 水平溢出 0px，沒有元素超出視窗
- 按鈕、chip、導覽項目皆 ≥ 44×44px；Accordion 標題 ≥ 56px

有一處我沒有照規範原文寫。§2.5 訂卡片網格為 `minmax(320px, 1fr)`，
但視窗剛好 320px 時，320px 的卡片加上左右各 24px 內距會溢出 39px。
`styles.css` 改用 `minmax(min(320px, 100%), 1fr)`：寬螢幕維持 320px 下限，窄螢幕自動退成滿寬。

## 無障礙

規範 §4 的驗收條件，這份範例已經實作的部分：

- 每個可聚焦元素 3px focus-visible 外框、offset 2px
- Skip link、單一 `h1`、標題階層不跳級
- chip 群組 `role="tablist"` + 左右方向鍵循環 + roving tabindex
- 篩選數量以 `aria-live="polite"` 播報
- Accordion 收合面板用 `hidden`，移出無障礙樹，Tab 不會進去
- 表單錯誤同時用顏色、文字、`aria-invalid` 表達，訊息以 `aria-describedby` 綁定並放在 `role="alert"` 裡
- `prefers-reduced-motion` 下所有動畫縮至 0.01ms

規範定義但這份**基本**範例沒有做的：Dropdown（§3.4）、Pagination 的完整行為（§3.7）、
卡片骨架載入（§3.6 `.card--skeleton`）。需要時照規範的行為表補上。

## 規範缺口（請留意）

以下四個 token 在 `STYLEGUIDE.md` §3 被引用，但 §2.1 的色彩表**沒有給值**。
`tokens.css` 裡的數值是我為了讓範例能跑而推導的，**不是規範原文**，
取得正式值後請直接覆蓋：

| Token | 推導值 | 怎麼來的 |
|---|---|---|
| `--color-border` | `#becad7` | 等於 `text.tertiary`，其用途已寫「深色底文字、**分隔**」 |
| `--color-border-strong` | `#7690a8` | 白底 3.32:1，滿足 §4「元件邊界 ≥ 3:1」。原本的 `#becad7` 只有 1.66:1，當輸入框邊框不合格 |
| `--color-disabled-fg` | `#8a9aab` | 於 `disabled.bg` 為 2.56:1，可辨識但明顯非啟用態 |
| `--logo-ink` | `surface.strong` | §3.11 有寫規則但沒給 token 名。淺色底刻意用主色藍而非規範原文的 `brand.ink` 近黑 |

另外規範本身有兩處前後不一致，這份範例一律採用 §2.1 的**色彩 token 表**為準：

1. §2.1 訂裝飾色為 `#f5d35b`／`#ef9d78`、danger 為 `#b3261e`；
   文末「畫面生動化」附錄卻寫成 `#FCD12E`／`#EF9D55`／`#D32F2F`，且未定義 `Neutral 200`。
2. §2.1 說裝飾色「不得作為文字色或狀態色」；附錄卻要求拿它當徽章與強調色。
   範例採 §2.1：`.badge` 白底配藍字（7.97:1），裝飾色完全不進元件層。
   這也和 §3.12 一致 —— 功能選單的色塊底色「一律 `#FFFFFF`，不隨主題色變化」。

還有一個小出入：§2.1 對比表寫 `#b3261e on #fdf1f0` 為 6.04:1，實際計算為 **5.92:1**。
仍通過 AA，不影響使用，但數字建議更正。

## 檢查清單

交付前照規範 §7 逐項確認：

- [ ] 所有顏色、間距、字級、圓角、陰影、動態皆來自 `tokens.css`
- [ ] 每個互動元件的七種狀態都能重現
- [ ] 320 / 768 / 1280 三個斷點無水平捲軸、無重疊
- [ ] 長標題、長摘要、空清單、載入中、錯誤五種情境都有處理
- [ ] Tab 走訪全頁，焦點始終可見且不進入隱藏元素
- [ ] 每頁單一 `h1`，標題階層無跳級
- [ ] `prefers-reduced-motion` 開啟時無持續播放的動畫
